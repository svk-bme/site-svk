# Event check-in (Google Apps Script)

A script that lives in one event's Google Forms response spreadsheet. It emails each registrant a QR code, sends a
reminder before the event, and serves the check-in page staff open by scanning the codes. The website itself is not
involved; it only links to the Google Form. Setup for editors: [EDITING.md](../../EDITING.md) → "Event registration".

| File | What it is |
| --- | --- |
| `Code.gs` | The script: menu and setup, form-submit and hourly triggers, emails, check-in page |
| `QrCode.gs` | [qrcode-generator](https://github.com/kazuhikoarase/qrcode-generator) 1.4.4 (MIT), unchanged, so QR codes are drawn in the script instead of by an online QR service |
| `appsscript.json` | Manifest: Budapest time zone, the four permissions it needs, web app settings |
| `Code.test.mjs` | Runs `Code.gs` against fakes of the Apps Script services (`npm test`) |

## How it works

- **Columns.** Setup adds `Kód`, `Ismételt jelentkezés`, `Visszaigazolás elküldve`, `Emlékeztető elküldve`,
  `Megjelent` and `Beléptette` to the response sheet. The script finds columns by header, so the form's questions can
  change. The email and name columns are found by header (`e-mail`, `név`/`name`) unless set in **Beállítások**.
- **Settings.** The `Beállítások` sheet holds everything event specific: texts, times, the check-in link and PIN.
- **Codes.** `Utilities.getUuid()` gives 122 random bits per registration, so codes cannot be guessed.
- **One email per address.** A later registration with an address already in the sheet is marked as a repeat and gets
  no code or email, so the form cannot be used to flood someone's inbox. An address that someone else typed in gets one
  email, which says how to have the data deleted.
- **Check-in page.** The web app runs as the account that deployed it, so attendees never see a Google permission
  screen. It changes nothing without the event's staff PIN (12 characters, about 60 bits, generated by setup, kept on
  each staff phone in the browser's local storage), and it shows only the name and the state. Checking in is a script
  call from the page, not the link itself, so link previews and scanners in email systems cannot check anyone in.
- **Permissions.** `spreadsheets.currentonly` (only this spreadsheet), `script.send_mail` (send as the account,
  without reading its mail), `script.scriptapp` (create the triggers), `script.container.ui` (the menu and dialogs).

## Changing the script

Edit the files here and run `npm test`. Each event's spreadsheet holds its own copy, so a change reaches only the
events where the new files are pasted in. Test a new version in a copy of a spreadsheet: the test email, a registration
from the form, and one check-in on a phone.
